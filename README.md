# Qwen3-TTS Console

A local text-to-speech studio for Apple Silicon Macs, built around [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) running on [MLX](https://github.com/ml-explore/mlx). It looks and works like a small piece of studio hardware: pick a voice cartridge, turn the knobs, generate a script paragraph by paragraph, and export the final mix.

## What it does

- **Script-first workflow.** Paste a script; blank lines split it into paragraphs. Each paragraph can have several takes, and the selected take goes into the final mix.
- **Consistent voice across a long script.** When one paragraph sounds right, click **Make voice**: that take becomes a custom voice, and the rest of the script is generated by cloning it.
- **Voice library.** The 9 built-in voices (Chinese, English, Japanese, Korean, Beijing and Sichuan dialects) plus your own cloned voices, filterable by language and gender.
- **Zero-shot voice cloning.** Upload 5–15 seconds of someone speaking plus the exact transcript, and save it as a named voice. No training. Optional automatic transcription with faster-whisper.
- **Post-processing that never needs regenerating.** Speed (pitch-preserving), breath and pause removal and the gap between paragraphs are rendered with ffmpeg at playback and export time, so turning a knob is instant.
- **Export** as one WAV, one MP3, or a ZIP with one WAV per paragraph for lining up in a video editor. Any single paragraph can also be downloaded on its own.
- **Runs entirely on your Mac.** One generation at a time on the GPU; models load on demand and unload after 10 idle minutes.
- Chinese and English UI, light and dark mode, keyboard shortcuts, works on a phone.

## Requirements

- A Mac with Apple Silicon. Tested on an M5 Pro with 64 GB; generation peaks at about 6 GB of memory.
- Python 3.10 or newer (tested with 3.13) and [ffmpeg](https://ffmpeg.org) (`brew install ffmpeg`).
- About 6 GB of disk space for the two models.

## Quick start

```bash
git clone https://github.com/shisaq/qwen3-tts-console.git
cd qwen3-tts-console
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# the two 8-bit MLX models (about 3 GB each)
.venv/bin/hf download mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-8bit --local-dir models/Qwen3-TTS-12Hz-1.7B-CustomVoice-8bit
.venv/bin/hf download mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit --local-dir models/Qwen3-TTS-12Hz-1.7B-Base-8bit

.venv/bin/python ttsd.py
```

Then open <http://127.0.0.1:18400>. The CustomVoice model powers the built-in voices; the Base model powers cloning. If you only need one of them, download only that one.

## Configuration

Settings are read from `~/.config/ttsd/config.json` (or the file named by `TTSD_CONFIG`). Every key is optional; see [`config.example.json`](config.example.json).

| Key | Default | Meaning |
| --- | --- | --- |
| `host`, `port` | `127.0.0.1`, `18400` | Where the server listens |
| `models_dir` | `models` | Folder containing the model folders (relative to the repository) |
| `preset_model`, `clone_model` | the 1.7B 8-bit models | Folder names inside `models_dir` |
| `data_dir` | `~/.local/share/ttsd` | Scripts, takes, custom voices, exports |
| `ffmpeg` | from `PATH` | Path to ffmpeg |
| `transcribe_python` | off | A Python interpreter that has `faster-whisper` installed; enables automatic transcription of reference recordings |
| `whisper_model` | `base` | faster-whisper model name |
| `idle_unload_minutes` | `10` | Unload models after this much idle time |
| `device_name` | empty | Shown on the nameplate |
| `home_url` | empty | Adds a "Back to home" link to the top bar |

## Using it

1. **New script** → paste text. Each blank-line-separated block becomes a paragraph.
2. Pick a voice in the **voice library**. For system voices you can describe the **mood** ("calm, steady and persuasive"; Chinese works too). Choose the **language**, or leave it on Auto.
3. Click **Generate** on a paragraph (or press <kbd>G</kbd>). Generate again for another take; click the take numbers to compare.
4. Happy with one paragraph? Click **Make voice**, then **Generate remaining** (<kbd>A</kbd>) to do the rest in the same voice.
5. Adjust **speed**, **breath**, **pause** and **gap** while listening, then **Export**.

Keyboard: <kbd>G</kbd> generate · <kbd>A</kbd> generate remaining · <kbd>Space</kbd> play/pause · <kbd>Shift</kbd>+<kbd>Space</kbd> play all · <kbd>↑</kbd><kbd>↓</kbd> move · <kbd>1</kbd>–<kbd>9</kbd> pick take · <kbd>⌘</kbd><kbd>Enter</kbd> generate while editing · <kbd>B</kbd> export · <kbd>Esc</kbd> stop.

### Cloning tips

- 5–15 seconds of one speaker in a quiet room works best. Longer is not better.
- The reference text must match the recording **word for word**; it matters more than anything else for likeness. Check automatic transcriptions carefully.
- The tone of a cloned voice comes from the reference recording, so the mood field is disabled for custom voices.
- This is zero-shot cloning. Qwen3-TTS also supports fine-tuning a dedicated voice, but the official recipe targets CUDA GPUs and is not part of this project.

## Running in the background

[`launchd/com.example.ttsd.plist`](launchd/com.example.ttsd.plist) starts the server at login on macOS. Replace the paths, copy it to `~/Library/LaunchAgents/` and run `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.example.ttsd.plist`.

## Security

There is no login. The server listens on `127.0.0.1` by default; to use it from other devices, put it behind a reverse proxy that only your own devices can reach (a VPN such as Tailscale, or a proxy with authentication). Do not expose it to the internet as is.

## Notes

- **MLX 0.32 or newer is required.** With MLX 0.30 on M5-class GPUs, generated speech contains chunks of digital silence about every 1.2 seconds, with no error.
- The model's own `speed` parameter has no effect, which is why speed is a post-processing step.
- The first playback opens the audio output once and keeps it open, so Bluetooth and HDMI outputs do not swallow the start of each clip.

## Tests

```bash
.venv/bin/python -m unittest discover tests
```

The tests cover text splitting, settings validation, post-processing and the HTTP API; they do not need the models.
